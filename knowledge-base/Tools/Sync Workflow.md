# Sync Workflow — Linear ↔ GitHub ↔ Knowledge Base

We keep three systems in sync for NOUS SPACE:

1. **Linear** — tasks, issues, project tracking (workspace NOUSSPACE, project "NOUS SPACE Website" `P-NOU-1`).
2. **GitHub** — code and version history (`NOUSSPARK/NOUSSPACE`).
3. **Knowledge base** — Obsidian vault in `knowledge-base/` (references, tools, ideas, decisions).

## Convention

- When starting work: create/claim a Linear issue; note it in the KB (Ideas/Notes) if it's exploratory.
- When committing: reference the Linear issue ID in the commit message (e.g., `NOU-12: add contact page`).
- When finishing: mark the Linear issue Done; update KB (Tools/References) if new tools/patterns were introduced; push to GitHub.
- References/inspiration go in `knowledge-base/References/` and are tagged `#highlight` when notable.
- New tools/integrations get a note in `knowledge-base/Tools/`.
